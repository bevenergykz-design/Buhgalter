# Сайт ТОО «Образцовая бухгалтерия „Диалог Учёт“»

Корпоративный сайт на русском и казахском языках, личный кабинет клиента и панель управления для сотрудников.

| Часть | Адрес | Кто пользуется |
|---|---|---|
| Сайт (RU) | `/`, `/uslugi`, `/novosti`, `/o-kompanii`, `/kontakty` | посетители |
| Сайт (KZ) | `/kk`, `/kk/uslugi`, … | посетители |
| Личный кабинет клиента | `/cabinet` (кнопка «Личный кабинет» в шапке) | клиенты: регистрация, документы, отчётность, сообщения |
| Панель управления | `/admin` (ссылка «Вход для сотрудников» в подвале) | сотрудники: заявки, клиенты; администратор — ещё и контент сайта |

Инструкция для сотрудников компании — [docs/ИНСТРУКЦИЯ.md](docs/ИНСТРУКЦИЯ.md).

## Технологии

- Node.js ≥ 22.13 (используется встроенная база `node:sqlite`, нативных модулей нет)
- Express 4, шаблоны EJS, без сборки фронтенда
- Зависимости: `express`, `ejs`, `multer` (загрузка файлов), `nodemailer` (почта)

## Запуск локально

```bash
npm install
npm start          # http://localhost:3000
npm test           # сквозная проверка на временной базе (83 проверки)
```

При первом запуске создаётся администратор. Его e-mail и пароль записываются в `data/FIRST-ADMIN.txt` — после входа смените пароль и удалите файл. Можно задать данные заранее: переменные `ADMIN_EMAIL` и `ADMIN_PASSWORD`.

Создать администратора или сбросить ему пароль из консоли:

```bash
node scripts/create-admin.js manager@example.kz "Имя Фамилия"
```

## Где хранятся данные

Всё изменяемое лежит в одной папке `data/` (путь меняется переменной `DATA_DIR`):

- `data/site.sqlite` — база: тексты, услуги, новости, страницы, отзывы, заявки, клиенты, отчёты, переписка, настройки;
- `data/files/` — документы клиентов (закрытые, отдаются только после входа);
- `data/uploads/` — изображения сайта (обложки новостей, фото), доступны по `/uploads/…`;
- `data/backups/` — автоматические ежедневные копии базы (хранятся 14 последних).

Папка `data/` не попадает в Git. На сервере её нужно сохранять при обновлениях и включить в резервное копирование хостинга. Полный архив (база + файлы) скачивается в панели: «Резервные копии».

## Развёртывание на Plesk (Node.js)

1. Включить расширение Node.js, версия **22.13 или новее**.
2. Подключить репозиторий (Git → автоматическое развёртывание) в корень приложения.
3. Настройки Node.js: *Application startup file* — `server.js`, *Application mode* — `production`.
4. Переменные окружения:
   - `NODE_ENV=production`
   - `DATA_DIR=/var/www/vhosts/<домен>/private/dialog-data` — папка вне каталога сайта, чтобы деплой её не трогал;
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` — только для первого запуска.
5. `npm install` (кнопка NPM install), затем Restart App.
6. Включить SSL (Let's Encrypt) и перенаправление на HTTPS.
7. В панели сайта → «Уведомления и интеграции»: e-mail для заявок, SMTP, адрес сайта, Google Analytics / Tag Manager / Search Console.

Сайт также работает на любом VPS: `NODE_ENV=production DATA_DIR=/srv/dialog-data node server.js` за Nginx/Apache с проксированием на порт `PORT` (по умолчанию 3000).

## Безопасность

- Пароли хранятся только в виде хеша scrypt; сессии — в базе, cookie `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS.
- Все изменяющие запросы кабинета и панели защищены CSRF-токеном.
- Ограничение попыток входа, регистрации и отправки заявок; скрытое поле-ловушка и проверка времени заполнения от спам-ботов.
- Роли: «Бухгалтер» (заявки и клиенты) и «Администратор» (плюс контент, настройки, сотрудники, резервные копии).
- HTML из визуального редактора очищается от скриптов и опасных ссылок.
- Документы клиентов не лежат в публичной папке; клиент видит только свои файлы.
- Панель и кабинет закрыты от индексации (`robots.txt`, `X-Robots-Tag`).

## Интеграция с CRM

В «Уведомления и интеграции» указывается адрес вебхука. Сайт отправляет на него POST с JSON при событиях `lead.created`, `lead.updated`, `client.registered`, `client.status`. Заявки также выгружаются в CSV из раздела «Заявки».

```
public/                CSS, JS, изображения
scripts/               smoke-test.js, create-admin.js

```
